# بنية المشروع

## قرار التصميم

الدرس والتحضير ينطلقان من بيانات واحدة، بدل صيانة صفحة HTML وخطة منفصلة لكل وحدة. العرض التفاعلي يولد عناصر الواجهة من نصوص موثقة؛ التحضير يولد HTML من النصوص نفسها. الإضافة تستورد حزمة مراجعة ولا تحصل على حساب GitHub أو كلمة مرور نور.

## الملفات

| المسار | الوظيفة |
|---|---|
| index.html | هيكل المكتبة والحوارات |
| assets/style.css | لغة التصميم الموحدة، RTL، الاستجابة والطباعة |
| assets/app.js | الدروس والتدريب والتأمل والمحرر المحلي |
| assets/core.js | تحقق المحتوى وتوليد التحاضير المشتركة |
| content/catalog.json | المصدر المعتمد للمناهج والوحدات والدروس |
| assets/catalog.js | بيانات الموقع المولدة للتشغيل دون اتصال |
| extension/ | إضافة Firefox: لوحة محتوى، خلفية، محول نموذج نور |
| scripts/ | بناء واختبارات وتغليف |
| downloads/ | ZIP الإضافة وحزمة المحتوى المولدة |
| .github/workflows/pages.yml | تحقق وبناء ونشر GitHub Pages |

## تدفق المحتوى

`catalog.json → core.validate → الموقع + core.plans → إضافة نور → نموذج المعلم → مراجعة وحفظ يدوي`

التعديلات المحلية تصدر إلى حزمة تحتوي `format`, `version`, `catalog`. الحزمة نفسها تستوردها الإضافة. لإصدار رسمي، يراجع catalog ويستبدل المصدر في Git ثم يبنى الموقع والإضافة معًا.

## حدود الوحدات

- طبقة المحتوى لا تعرف حسابات أو بيانات طلبة.
- طبقة العرض تحفظ سجلًا محليًا فقط.
- إضافة Firefox محدودة إلى نطاق نور، وتقبل أوامر التعبئة من لوحتها فقط.
- محول نور يبحث عن الدرس داخل فرع الوحدة، ويزيل شارات كتاب/فصل/وحدة/درس من النص.
- لمطابقة أهداف نور: ربط مرصود يتحقق منه وقت التشغيل، أو مراجعة يدوية عند عدم التطابق. لا يكتب HTML قادمًا من مصدر عشوائي؛ يولده من حقول نصية مفحوصة.

## التوسع لاحقًا

يضاف المنهج إلى courses دون إنشاء محرك عرض جديد. يمكن توسيع المخطط مستقبلًا بمقاطع برمجية وصور مرخصة وموارد محلية وأنواع ألعاب جديدة، مع رفع schemaVersion وإضافة انتقال بيانات واختبارات. لا توجد قاعدة بيانات أو حسابات في هذا الإصدار؛ مزامنة المعلمين والطلبة تحتاج تصميم صلاحيات وخادم منفصلًا.
