# Project update workflow

For every requested update, review the current library, learning journey, development studio, Noor preparation section, question bank, and project guide. Update sections whose displayed content, counts, links, instructions, or behavior need to change; leave unaffected sections unchanged. Record which sections changed and which were reviewed without requiring changes in the release notes.

Use current catalog and question-bank data for counts and availability. Keep contextual links aligned with their grade, unit, and lesson. Preserve the simple classroom question display. Validate affected behavior and publish authorized updates to the existing GitHub Pages project. Do not claim browser visual QA when only automated or DOM-harness checks were available.
